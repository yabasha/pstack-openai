### Session pickup

**You own the resume point. Read the prior trail, don't redo it.**

Use [session capabilities](../../../references/host-capabilities.md) to observe history, file reads, execution and persistence separately. Follow the [assignment contract](../../../references/orchestration-contract.md) for revision, ownership and interrupted actions, and [model roles](../../../references/model-roles.md) for supported inherited selection. A transcript reference does not prove access or continuity. This playbook grants no new permissions.

1. Locate the prior trail. Use a transcript in the active workspace's explicitly identified agent-transcripts directory, an accessible cloud-agent URL, or the supplied pushed branch. Read only the scoped trail. Never search unrelated workspace histories or private chats. Read the metadata overview and last messages first, then scan back for decision points. Read [principle-guard-the-context-window](../../principle-guard-the-context-window/SKILL.md) in full. Parse a long transcript with an authorized independent worker only after observing its binding and inspecting its result. Otherwise read bounded sections sequentially, retain a reduced timeline in the main thread and label reduced capability. Missing history or denied access leaves the reconstruction provisional. Name the missing input; do not invent prior turns or broaden access.
2. Reconstruct operational state. Recover the branch and worktree, original goal, what already landed, open todos and decisions. Record the prior full input SHA and assignment or action identities when present. Inspect actual current branch, worktree, full HEAD SHA, git log and git diff against the recorded base through exposed authorized read or execution tools. Compare the trail with these observations before acting. The prior trail is authoritative input for prior decisions, but a self-report does not prove current state. Reject stale assignment results whose revision or identity does not match. Preserve concurrent work; do not reset or overwrite it. If the base, revision or artifact is inaccessible, state the gap and stop dependent actions.
3. Diff done vs pending. Compare what shipped against what was planned, name the resume point, and retain completed work. Do not re-run the prior repro or redo completed work merely to verify from scratch. Inspect only evidence needed to reconcile current state and verify inherited claims. Resolve a changed revision or contradictory artifact before continuing dependent work. Preserve inherited authorization, explicit gates and pending decisions. For an interrupted external action, inspect its stable identity, intended destination and actual prior outcome. Unknown outcomes block replay. Recovery requires explicit authorization, destination inspection and observed safe idempotent recovery under the assignment contract; a retry policy does not establish success.
4. Route remaining work to the matching playbook in [poteto-mode](../SKILL.md). Pick the verdict: continue execution, ship a finished recommendation, ratify or override a prior conclusion, or postmortem a failed run. Read the routed playbook in full before dependent work. If it is missing, name that dependency and stop the route. The pickup playbook ends here. The routed playbook owns the rest, including its permission and review gates.
5. Verify inherited claims against the original goal on the real artifact using [principle-prove-it-works](../../principle-prove-it-works/SKILL.md), read in full. A passing prior self-report is not proof. Retain actual inspection evidence and name unverified outputs. If a durable continuation record is authorized and needed, save it in the scoped owned location and verify readback. Without observed persistence, report a session-local reduced handoff; do not claim saved state, unattended recovery or cross-session continuity.

**Reply:** where the prior agent stopped, what you inherited vs redid, ideally nothing redone, the resume point, and the outcome. Include the actual revision comparison, route or verdict, evidence and any history, permission or persistence limits. Distinguish verified completion from a provisional recommendation.
