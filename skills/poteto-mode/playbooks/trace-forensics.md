### Trace forensics

You own the diagnosis from the artifact. Load it, shape it, narrow to the cause, attribute to source.

Distinct from [Runtime forensics](runtime-forensics.md), which instruments the live process. Here the capture already exists. The artifact is a fixed dataset. Read it, don't re-run it. Keep tooling generic so the playbook stays portable. Use an available DevTools or trace parser for cpuprofile and `.json.gz`, a text editor for a spindump, and heap tooling for a heapsnapshot.

Read the complete [poteto mode](../SKILL.md), [session capabilities](../../../references/host-capabilities.md), [model roles](../../../references/model-roles.md), [assignment contract](../../../references/orchestration-contract.md) and [poteto role prompt](../../../references/agent-prompts/poteto-agent.md). Discover actual artifact-read, parser, execution and local storage operations. Use only authorized operations and output paths. Missing required reads stop dependent work. Do not install a parser or upload an artifact implicitly.

1. Identify the format and load it with the right available tool. Retain the exact artifact identity and path, format and capture metadata it actually carries. Preserve the original bytes. Parse large artifacts in an authorized independent worker under the complete [guard-the-context-window](../../principle-guard-the-context-window/SKILL.md) contract and keep the reduced finding in the main thread. Supply the full poteto prompt, exact input revision and distinct owned output. Inspect the result and its artifact citations. Use inherited model roles unless selection is supported and observed; record requested and actual values separately. Without authorized workers, use bounded sequential parsing as reduced capability. Missing artifact access or a suitable parser blocks dependent analysis, never an invented read.
2. Transform the raw artifact into a form you can query. Dump the trace or heap snapshot into sqlite, one row per sample, frame, or node. Reach the queryable shape before you read for diagnosis. Preserve original sample or event order, timestamps, frame or node identities, parent or retainer relationships and links back to the original artifact locations. Derived data must identify its source artifact. Write the derived database only to an authorized local output. If sqlite conversion or storage is unavailable or denied, disclose the missing gate. An available read-only queryable representation is reduced capability and does not prove the sqlite dump ran.
3. Narrow to the cause. Query for the frames that hold the most time and walk the call tree to the hot path. For a leak, follow the retainer chain from the leaked object to a GC root. For a spindump, find the thread stuck on-CPU or blocked and its wait reason. Cite the exact artifact records supporting the reduced finding. Do not substitute a new capture or reconstructed event order.
4. Attribute to source. Map the hot frame to file, symbol, and line via the artifact's own symbols. A frame with no source mapping is not yet a diagnosis. Resolve the symbols with available authorized tools, or say plainly the artifact does not carry them. Keep artifact and source citations together. Missing source access or unresolved mapping leaves a complete mapped diagnosis blocked; do not invent a line or silently use symbols from a different revision.
5. Confirm against a paired capture when you have one. Diff a before and after artifact, preserving each identity and the actual comparison evidence. Without one, mark the finding as the strongest hypothesis the artifact supports, not a confirmed cause. An inaccessible or incompatible pair cannot confirm the finding. Do not run the process to manufacture a pair within this fixed-artifact workflow.
6. Hand back a cited diagnosis, no fix unless asked. Route to [Bug fix](bug-fix.md) or [Perf issue](perf-issue.md) once the cause is known. Diagnosis does not authorize implementation or external writes. Throughput checkpoint stays one line: `throughput checkpoint: n/a, read-only forensics`.

Reply with the artifact and format, the reduced finding, the source location, the artifact paths, and whether a paired capture confirmed it. Include the derived query artifact when produced and explicit access, parser, mapping or worker limits. Preserve the exact trace identity, order and source links in every cited finding. Label an unpaired finding as a hypothesis.
