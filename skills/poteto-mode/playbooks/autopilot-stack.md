### Autopilot-stack

Run Autopilot-full within authorized scope, without merging. Build and verify PRs for the operator to land. Independent items branch from trunk. A PR stacks only on a PR it actually builds on. Use for "autopilot-stack", "stack them, don't ship", or "build the stack, I'll land it".

Read [poteto-mode](../SKILL.md), [Autopilot-full](autopilot-full.md), [session capabilities](../../../references/host-capabilities.md), the [assignment contract](../../../references/orchestration-contract.md), [model roles](../../../references/model-roles.md), and the [poteto role prompt](../../../references/agent-prompts/poteto-agent.md) in full. Inherit the parent model unless explicit selection is supported. Actual models remain unknown until observed. Discover execution, forge, independent workers, history, persistence, wake and stop bindings. Upstream autonomy grants no permission. Commits, pushes, PR creation, retargets, verdict posts and other external writes require actual authorization and observed outcomes. Never install or schedule implicitly.

Read each complete adapted dependency before its step. The [Bugbot rubric](../references/bugbot-triage.md), [Babysit](babysit.md), [Shipping](shipping.md), and [Opening a PR](opening-a-pr.md) may be pending. A missing contract blocks its dependent operation. A canonical-source read during implementation does not supply an executable adapted contract. Continue only independent authorized work and report the exact gap.

1. Run the owner loop unchanged except for this playbook's topology and landing rules. Resolve the forge once for the program. GitHub CLI (`gh`) is the default. If `command -v origin` succeeds and Origin can resolve the repository, use `origin pr ...` for PR operations. Otherwise stay on `gh` and record the fallback. Never require Graphite (`gt`). Assign one independent worker per PR under the full poteto role prompt and assignment contract. The owner builds, makes the first authorized push, opens a ready PR before self-proof, runs gates and CI with receipts, triages Bugbot skeptically, completes the discovered `deslop` companion or an authorized replacement review, runs [/no-comments](../../no-comments/SKILL.md), and babysits to green. Report a missing companion as an unmet gate, never silently waive it. Owners parallelize self-contained work with disjoint files and one writer per branch. Soon after actual dispatch, every authorized owner starts an uncommitted `decisions.tsv` via [show-me-your-work](../../show-me-your-work/SKILL.md), pushes its first snapshot and opens the PR ready, never draft. Only within an explicit push grant, push each finished unit before starting the next, with hooks on. Keep and return the trail. Keep `children.tsv` as in Autopilot-full step 2, with child identity, expected runtime and state. Missing runtime history stays unknown, not an invented timeout. Retain committed-head pre-review checks. Each PR owner is the sole branch writer and performs its authorized rebases. The root coordinates dependency order and never competes as a topology writer. For a dependent item, branch from the intended parent item's branch rather than trunk.
2. Audit on a real loop. On the operator's go, register an exposed, authorized hourly wake with a prompt for this tick. The source alias `/loop 1h` is not a portable scheduler binding. Observe registration identity, cadence and stop operation before claiming it active. At each tick, re-read both this playbook and Autopilot-full from trunk; this playbook wins where they differ. Re-read this playbook from trunk using `git show <observed-trunk-ref>:<actual-repository-relative-playbook-path>`, record both values and verify the read. Audit against it and fix drift. Probe every owner with a generic liveness or status check. Count only commits, pushes, PR or check deltas and store reports as progress. Stand down and replace a lane that errors or exceeds an observed expected runtime without side effects, without waiting for a polite return. Apply Autopilot-full step 6's agent-list and children checks, repeat replacement checks, collect trails, and finish the tick only when no delegated work remains. If stop cannot be observed, issue zero-writes orders, record unverified termination, inspect reachable state and quarantine partial artifacts. Do not dispatch a competing writer until ownership is safe. Missing persistent wake permits useful authorized current-turn ticks and a saved continuation brief as reduced capability; it never promises hourly work after the turn.
3. Hold the operator gates. State-then-wait applies. A request to state the plan is not a go. On the operator's stop, every owner takes an immediate zero-writes hold and retains its brief until released.
4. Verify each round. The owner reports its code-ready head SHA once the shipped code is final, and `VERIFIED-HANDOFF` with the exact head SHA when self-proof, CI and babysit are green. Apply Autopilot-full step 4 in full with VERIFIED-HANDOFF in place of merge-ready. Audit receipts, run independent [swarm](../../swarm/SKILL.md) lanes at that exact revision, re-run gates, prove load-bearing behavior on the real artifact per [prove-it-works](../../principle-prove-it-works/SKILL.md), audit the diff with at least two focused lanes, and run the same regression scenario on current trunk. If trunk lacks the feature, record that and verify the added behavior and user end state. A live lane is mandatory. Send every proven finding, including notes, in one fix-forward with red tests covering all defect sites or a repro receipt. Add the defect to the next brief. Use Autopilot-full's review cadence: full swarm at code-ready and again for new behavior, redesign or a large new diff; a rebase, conflict resolution or minor fix gets one independent verifier at the new head. Apply the same narrowly evidenced wording-only exception as Autopilot-full; changed instructions, permissions, gates or shipped facts still need review. Every head needs green CI and a fresh applicable verdict. Shipping's patch-id rule governs carried lanes. Nothing enters the stack unverified.
5. Stop at verified, never ship. No owner or root merges, arms auto-merge, or closes a PR under this playbook. Publish a current verdict only when external posting is authorized. Otherwise retain local artifacts and report reduced delivery. The operator owns landing. After handoff nobody pushes again without the operator's go. Every authorized wake prompt names this no-merge playbook.
6. Give each branch one writer. The PR owner alone rebases onto its actual parent branch, with the stack root on trunk. The root coordinates parent-before-child work and retarget requests. Before topology changes, inspect branch ownership, exact parent tip, current remote tip and prior action outcome. Pin force-with-lease to the remote SHA last pushed or explicitly taken over. Unexpected pushes or unknown previous outcomes block replay. No shared branch force-push. Retargeting or closing a base can orphan children, so coordinate it with the root and operator within explicit authorization. If a prior root-owned chain is resumed, use a zero-writes hold and explicit ownership transfer before changing topology. Never let old and new ownership policies write concurrently.
7. Absorb parent drift and re-verify. A changed parent head triggers owner-driven restacking in dependency order. Apply Autopilot-full's current-trunk impact test to the actual parent. Every rewritten head needs fresh mergeability and green CI. Carry a lane only under Shipping's complete head/base/patch-id and build-noise rules; an unchanged patch-id alone is insufficient. Changed behavior returns to step 4. A new budget or gate relaxation still needs fresh countersign after verifier proof and never bypasses a forge gate. Record the exact base, head, patch-id and verdict revisions.
8. Deliver verified PRs with their current heads, parents, verdicts and capability gaps. List independent PRs separately from genuinely dependent chains. Posting requires explicit authorization; local preparation is not published delivery. Once the operator starts landing, hold writes. A later landing request routes to Shipping with fresh checks and separate authority. Never replay a completed create, push, retarget, verdict post or wake registration. Inspect each stable action identity and destination outcome before resuming; unknown outcomes block the affected action until reviewed safe recovery.

Before resuming and before another write, read back the continuation brief, decisions and children trails, assignment attempts, countersigns and operator gates. Resolve every PR's current head, base, intended parent, verdict head/base/patch-id, checks and mergeability against the live destination or authorized fixture. Reconcile changes with steps 4 and 7. Inspect each prior interrupted action's stable identity, destination and observed outcome, including pushes, creates, retargets, verdict posts and wake registration. Completed actions are not replayed. Unknown outcomes block replay; safe recovery requires explicit authorization, destination inspection and an appropriate idempotency mechanism. A saved head or completion notification never proves current state. Missing history or inaccessible destinations leave affected writes blocked.

When independent owners or verifier lanes are unavailable, authorized sequential work is reduced capability and cannot satisfy the clean independent verdict gate. Missing real-artifact control leaves the live lane blocked. Keep unknown models and absent cross-model trail review explicit. Preserve show-me-your-work's Attention section and audit only this run's accessible transcript. Use its reviewed [log helper](../../show-me-your-work/scripts/log.sh) and [template](../../show-me-your-work/references/decision-log-template.tsv) with explicit owned local paths. Save and read back an authorized continuation brief with the dependency-ordered queue, branch ownership, exact heads/bases/parents, verdict revisions and patch-ids, pending actions and outcomes, trail paths, countersigns, gates, missing capabilities and next checks. If persistence is unavailable, return it inline and say no durable save occurred. Neither form proves unattended recovery or automatic pickup.

Choose Autopilot-full when landing authority is granted. Choose Autopilot-stack for operator review before landing or withheld merge authority. Dependency, not the playbook name, determines whether PRs stack.

Use [ketchup](../../ketchup/SKILL.md) to catch the operator up. Reply with links to each PR and any dependency chain, a one-line current verdict summary per link, and anything parked or excluded with its reason. Include open gates, capability gaps, trail and continuation paths, and Attention when a trail was produced. Do not fabricate PR links or describe a local proposed chain as a published stack.
