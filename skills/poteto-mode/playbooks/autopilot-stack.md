### Autopilot-stack

You own the stack, never the landing. Build and verify the queue within authorized scope, then hand the operator one linear base-branch stack to review and land. This is the sibling of Autopilot-full. Use for "autopilot-stack", "stack them, don't ship", or "build the stack, I'll land it".

Read [poteto-mode](../SKILL.md), [Autopilot-full](autopilot-full.md), [session capabilities](../../../references/host-capabilities.md), the [assignment contract](../../../references/orchestration-contract.md), [model roles](../../../references/model-roles.md), and the [poteto role prompt](../../../references/agent-prompts/poteto-agent.md) in full. Inherit the parent model unless explicit selection is supported. Actual models remain unknown until observed. Discover execution, forge, independent workers, history, persistence, wake and stop bindings. Upstream autonomy grants no permission. Commits, pushes, PR creation, retargets, verdict posts and other external writes require actual authorization and observed outcomes. Never install or schedule implicitly.

Read each complete adapted dependency before its step. The [Bugbot rubric](../references/bugbot-triage.md), [Babysit](babysit.md), [Shipping](shipping.md), and [Opening a PR](opening-a-pr.md) may be pending. A missing contract blocks its dependent operation. A canonical-source read during implementation does not supply an executable adapted contract. Continue only independent authorized work and report the exact gap.

1. Run the owner loop unchanged except for this playbook's topology and landing rules. Resolve the forge once for the program. GitHub CLI (`gh`) is the default. If `command -v origin` succeeds and Origin can resolve the repository, use `origin pr ...` for PR operations. Otherwise stay on `gh` and record the fallback. Never require Graphite (`gt`). Assign one independent worker per PR under the full poteto role prompt and assignment contract. The owner builds, makes the first authorized push, opens a ready PR before self-proof, runs gates and CI with receipts, triages Bugbot skeptically, completes the discovered `deslop` companion or an authorized replacement review, runs [/no-comments](../../no-comments/SKILL.md), and babysits to green. Report a missing companion as an unmet gate, never silently waive it. Owners parallelize self-contained work with disjoint files and one writer per branch. Within about 15 minutes of actual dispatch, every authorized owner starts an uncommitted `decisions.tsv` via [show-me-your-work](../../show-me-your-work/SKILL.md), pushes its first snapshot and opens the PR ready, never draft. Push again after every verifiable unit with hooks on; a WIP commit is fine. Keep and return the trail. Keep `children.tsv` as in Autopilot-full step 2, with child identity, expected runtime and state. Missing runtime history stays unknown, not an invented timeout. Retain that step's first-rebase, fix-round base and committed-head pre-review checks, with the root performing topology writes here.
2. Audit on a real loop. On the operator's go, register an exposed, authorized hourly wake with a prompt for this tick. The source alias `/loop 1h` is not a portable scheduler binding. Observe registration identity, cadence and stop operation before claiming it active. At each tick, re-read this playbook from trunk using `git show <observed-trunk-ref>:<actual-repository-relative-playbook-path>`, record both values and verify the read. Audit against it and fix drift. Probe every owner with a generic liveness or status check. Count only commits, pushes, PR or check deltas and store reports as progress. Stand down and replace a lane that errors or exceeds an observed expected runtime without side effects, without waiting for a polite return. Apply Autopilot-full step 6's agent-list and children checks, repeat replacement checks, collect trails, and finish the tick only when no delegated work remains. If stop cannot be observed, issue zero-writes orders, record unverified termination, inspect reachable state and quarantine partial artifacts. Do not dispatch a competing writer until ownership is safe. Missing persistent wake permits useful authorized current-turn ticks and a saved continuation brief as reduced capability; it never promises hourly work after the turn.
3. Hold the operator gates. State-then-wait applies. A request to state the plan is not a go. On the operator's stop, every owner takes an immediate zero-writes hold and retains its brief until released.
4. Verify each round. The owner reports its code-ready head SHA once the shipped code is final, and `STACK-READY` with the exact head SHA when self-proof, CI and babysit are green. Apply Autopilot-full step 4 in full with STACK-READY in place of merge-ready. Audit receipts, run independent [swarm](../../swarm/SKILL.md) lanes at that exact revision, re-run gates, prove load-bearing behavior on the real artifact per [prove-it-works](../../principle-prove-it-works/SKILL.md), audit the diff with at least two focused lanes, and run the same regression scenario on current trunk. If trunk lacks the feature, record that and verify the added behavior and user end state. A live lane is mandatory. Send every proven finding, including notes, in one fix-forward with red tests covering all defect sites or a repro receipt. Add the defect to the next brief. Every patch-changing push starts a fresh round except results valid under Shipping's patch-id rule. Nothing enters the stack unverified.
5. Append on a clean verdict, never ship. No owner merges, arms auto-merge, or closes a PR. The root also stops at delivery and never merges, closes a PR, or arms merge-when-ready under this playbook. Append a clean PR to one linear base-branch stack in verified order or the operator's specified order. Publication of each verdict in its PR body or comment remains an explicitly authorized write.
6. Keep one topology writer and parallel build writers. Owners push only their branches and report the tip, current base and intended parent. Coordinate a zero-writes hold on the affected owner branch before root topology work. The root alone fetches the intended parent, verifies its exact tip, rebases the child onto that tip, checks `ls-remote` and publishes with `--force-with-lease` only within authorization. Never force-push a shared branch. Follow Opening a PR's built-in PR tool contract for creation, edits, retargets and readiness when that tool is exposed. The following CLI examples apply only when it is not. Create a ready PR with `origin pr create --status open --base <parent-branch>` or `gh pr create --base <parent-branch>`. Retarget with `origin pr edit <pr> --base <parent-branch>` or `gh pr edit <pr> --base <parent-branch>`. Only the root PR targets trunk. Never submit or register the chain through `gt`. Read back each resulting head and base before accepting the topology.
7. Absorb drift at the root and re-verify what moved. Fetch current trunk and rebase bottom-to-top. Conflicts in an owner's files go to that owner for its own slice; the root pushes the result under the same exclusive topology ownership. Each rewritten SHA above the rebase voids the old verdict until Shipping's full patch-id rule validates its retained lanes. Record verdict head, base and stable base-to-head patch-id. Changed patches return to step 4. Tests, docs or lint-only differences use Shipping's two builds at the verdict SHA and one at current head, with each difference and noise explained. A dev-server lane or other lane without build output must rerun. Even an unchanged patch-id requires fresh mergeability and CI after every rewritten push. Preserve Autopilot-full's countersign rule: a genuinely new pinned gate or budget raise stops for a fresh root countersign after verifier proof, recorded under the approval contract and checked by a lane. Never bypass forge approval. Absorbing landed values is drift, not a raise.
8. Deliver one linear chain of verified PRs, reviewable bottom-up in the resolved forge. Every link carries its current verifier verdict in the body or comment when posting is authorized. If posting is denied, return local verdicts as reduced capability and do not claim forge delivery. The operator reviews and lands the chain with their own clicks or by arming merge-when-ready. A later authorized request to land routes to Shipping as a distinct workflow and requires its fresh checks.

Before resuming and before another write, read back the continuation brief, decisions and children trails, assignment attempts, countersigns and operator gates. Resolve every PR's current head, base, intended parent, verdict head/base/patch-id, checks and mergeability against the live destination or authorized fixture. Reconcile changes with steps 4 and 7. Inspect each prior interrupted action's stable identity, destination and observed outcome, including pushes, creates, retargets, verdict posts and wake registration. Completed actions are not replayed. Unknown outcomes block replay; safe recovery requires explicit authorization, destination inspection and an appropriate idempotency mechanism. A saved head or completion notification never proves current state. Missing history or inaccessible destinations leave affected writes blocked.

When independent owners or verifier lanes are unavailable, authorized sequential work is reduced capability and cannot satisfy the clean independent verdict gate. Missing real-artifact control leaves the live lane blocked. Keep unknown models and absent cross-model trail review explicit. Preserve show-me-your-work's Attention section and audit only this run's accessible transcript. Use its reviewed [log helper](../../show-me-your-work/scripts/log.sh) and [template](../../show-me-your-work/references/decision-log-template.tsv) with explicit owned local paths. Save and read back an authorized continuation brief with the bottom-to-top queue, branch ownership, exact heads/bases/parents, verdict revisions and patch-ids, pending actions and outcomes, trail paths, countersigns, gates, missing capabilities and next checks. If persistence is unavailable, return it inline and say no durable save occurred. Neither form proves unattended recovery or automatic pickup.

Choose Autopilot-full for independent PRs when landing authority is granted. Choose Autopilot-stack for sequenced or coupled work, operator review before landing, or withheld merge authority.

Reply with links to the stack root and tip, a one-line current verdict summary per link, and anything parked or excluded with its reason. Include open gates, capability gaps, trail and continuation paths, and Attention when a trail was produced. Do not fabricate PR links or describe a local proposed chain as a published stack.
