### Hillclimb

You own the metric and the experiment's integrity. Supervise and review. Delegate the attempts. For sustained, iterative improvement of one measurable thing against a target. A one-off fix is Bug fix or Perf issue. This is the loop.

Read the complete [poteto mode](../SKILL.md), applied leaves and their referenced contracts. Use [session capabilities](../../../references/host-capabilities.md), [model roles](../../../references/model-roles.md), the [assignment contract](../../../references/orchestration-contract.md) and full [poteto role prompt](../../../references/agent-prompts/poteto-agent.md). Preserve the active workflow owner. Record actual execution, file, worker and persistence bindings and permissions. Missing required reads stop dependent work. Do not install companions or set up scheduling implicitly.

Core discipline is one change, one measurement, keep or revert. Never stack untested changes, and never claim a win from code inspection. Apply [prove-it-works](../../principle-prove-it-works/SKILL.md).

1. Ground the workload and architecture before choosing the metric. Run the complete [how](../../how/SKILL.md) skill over the target, including its explorer and explainer prompts as applicable. Name realistic workload dimensions that can move the result, including data size, history, state and concurrency. Select a case that reproduces the user's complaint. If none reproduces it, fix the repro instead of hillclimbing. Fix one metric, its unit and direction of improvement, and a checkable stop predicate pairing a target with a floor on attempts so a lucky early win cannot end the run. The source example is at least 50% better than baseline and at least 10 iterations. Use the user's numbers when given, otherwise agree them before the loop.
2. Build the measurement harness, prove its sensitivity, then freeze it. Apply [build-the-lever](../../principle-build-the-lever/SKILL.md). Run contrasting realistic workloads and confirm the target reproduces the symptom while easier cases separate as expected. If it cannot distinguish them, revise the workload or metric. Vet it with the complete [benchmark-checklist](../../benchmark-checklist/SKILL.md) and [explain-the-number](../../principle-explain-the-number/SKILL.md) before freezing. Print error counts and completed-work counts. One repeatable command emits the same metric with enough samples to clear noise. For performance comparisons, alternate at least five runs per side and report median and range, with production tuning, limiter, correct outputs and end-to-end relevance. Record exact revisions, workload and configuration with each run. Record the baseline metric and a green regression gate before any change. Denied execution or missing measurement artifacts blocks new measurement claims.
3. Open the decision log via the complete [show-me-your-work](../../show-me-your-work/SKILL.md) skill and its [log helper](../../show-me-your-work/scripts/log.sh). Keep the canonical trail at an explicit owned, gitignored `decision.tsv` path outside committed changes. Use that skill's TSV format and append-only helper, not a second schema. One row per attempt records the source's id, hypothesis, change, before, after, delta, tests, kept or reverted verdict and note through its decision, why, evidence and result cells. Link an owned per-attempt artifact when the details do not fit single-line cells. Read the trail before each attempt and follow its pickup, transcript audit and cross-model review rules. Verify saved records by readback. Unavailable persistence or helper execution stays a visible block, not a claimed log.
4. Ground each hypothesis in step 1's architecture model so it names a specific mechanism, such as deferring work off the boot path because it blocks first paint. For a perf metric, order hypotheses by step 2's performance mantras in [Perf issue](perf-issue.md). Borrow only their order, not that step's stop rule.
5. Loop with one hypothesis per iteration:
   - Hand the change to an authorized independent worker with tight scope, exact input SHA, distinct owned output and the entire poteto role prompt. Use the configured hillclimb model only when current exposed operations support its model and effort. Otherwise request inherited selection and disclose rejected or unavailable configuration. Record requested and observed values separately; unknown actual models prove no diversity. An unavailable exact required selection blocks dispatch. Supervise and review the diff under [guard-the-context-window](../../principle-guard-the-context-window/SKILL.md). Several independent hypotheses may run in parallel only with authorized workers and separate worktrees under [separate-before-serializing-shared-state](../../principle-separate-before-serializing-shared-state/SKILL.md). Measure each isolated candidate against the same frozen harness and base. Integrate only reviewed, verified changes. Without workers, authorized sequential attempts are reduced capability and leave independent delegation unsatisfied.
   - Measure before and after with the frozen harness and run the regression gate. Keep the workload, metric and configuration comparable. Reject an inconclusive, error-producing or skipped-work result. A gap smaller than variation is no measurable difference.
   - Accept only when the metric moves past noise and the gate stays green. Otherwise revert the attempt's change in full while preserving unrelated work. A tweak that might help is not kept. Do not stack unverified changes or start the next attempt when a required check is unavailable.
   - Make one commit per accepted fix only when authorized, staging exact owned changed files, never all files. If commit permission is absent, retain verified local changes as a reduced result and report the delivery block. Log every attempt, kept or reverted, with its evidence.

   Each iteration ends in a check before the next begins under [sequence-verifiable-units](../../principle-sequence-verifiable-units/SKILL.md). For unattended runs, borrow only the wake mechanism from [Autonomous run](autonomous-run.md), never its stop rule. Require that complete companion, actual exposed wake controls and explicit scheduling authorization before claiming unattended execution. Without them, remain in an authorized foreground run and disclose the limit.
6. Push past the first plateau. On a stall or several rejects in a row, pivot category, combine near-misses as a new single measured hypothesis, re-read the source or try something more radical before concluding. Correctness and simplicity outrank the number. Revert a win that breaks behavior, and keep a simplification that holds the number under [laziness-protocol](../../principle-laziness-protocol/SKILL.md).
7. Stop when the predicate is met, or when remaining ideas are marginal and not worth their cost. Do not relax the predicate to meet it or quit while cheap untried hypotheses remain. If stuck, surface it instead of spinning. Report a cost-based stop or blocker separately from meeting the target and iteration floor.
8. Run the complete [Opening a PR](opening-a-pr.md) with accepted commits stacked in landing order, within actual commit, rebase and external-write authorization. Missing delivery dependencies stop delivery-dependent work. Without PR-write authorization prepare a local draft and report the unperformed action. Opening a PR does not start Babysit.

Reply with the metric and target, baseline to final with calculated percent delta, iterations run with kept and reverted counts, each accepted fix on one line, the actual `decision.tsv` path, and the best next idea if pushed further. Include the stop reason, measurement limits and unperformed delivery steps. A zero or invalid baseline cannot support a percent claim. Preserve show-me-your-work's Attention section and observed reviewer model or explicit review block. Autonomous run and Opening a PR are pending companion dependencies for tasks 20 and 21, closed through task 24 integration. Structural checks prove no host execution or improvement.
