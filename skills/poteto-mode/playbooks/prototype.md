### Prototype

You own the design decision, not the code. The prototype is a throwaway instrument. The real build follows Feature.

The one playbook where the Laziness Protocol's "smallest change" and the verification bar invert. Speed over polish, code quality does not matter, no planning. The rigor is in picking the right design cheaply. Propose variations the user did not ask for, throw an approach away and try another.

Read [poteto-mode](../SKILL.md) in full before work, including its companion gates and invocation aliases "prototype", "mock it up", "try this layout" and "sketch it to decide". Discover actual authorized tools through [session capabilities](../../../references/host-capabilities.md). Use [model roles](../../../references/model-roles.md) with inherited selection unless supported and observed. Any delegated probe follows [assignment and integration](../../../references/orchestration-contract.md) and the full [poteto role prompt](../../../references/agent-prompts/poteto-agent.md). No delegation is required by this playbook. Record the steps verbatim in the exposed todo list or an authorized local checklist with that reduced binding disclosed. No planning means no production implementation plan; capability and permission checks still apply.

1. Scope the decision the prototype exists to make: which layout, which interaction, which density, or for an empirical fork which behavior, timing, or approach. No decision means no prototype. Route to [Feature](feature.md).
2. Gather references when the design space is open. Search for prior art, summarize a moodboard of themes, palettes, and layouts, let the user pick directions before building. Skip when the direction is set. If reference search is unavailable, disclose the missing capability and label any unsupported design assumptions.
3. Build throwaway in an authorized isolated scratch dir, separate from production source. For a visual decision, vanilla HTML/CSS/JS or the lightest stack that renders the idea, CDN deps, a dev server with hot reload. For a behavioral or timing decision, the smallest script that exercises the question. No production framework, no tests, no abstractions. Use fixtures for read-only probes. CDN access, dependency setup and a network listener require actual permissions and setup authorization; do not install or start them implicitly. Prefer an available local static render when it can answer the same question and disclose the reduced binding. Bound the probe to the named decision and authorized scratch paths.
4. When comparing alternatives, build them behind one switcher, buttons or a keypress, each variant labeled. This is the [exhaust-the-design-space](../../principle-exhaust-the-design-space/SKILL.md) principle skill made cheap. Read its complete leaf and compare 2-3 distinct alternatives when its trigger applies.
5. Verify on the matching surface. For a visual decision, screenshot each variant via the available authorized control skill and drive the interaction. Discover the mode's control-ui companion and actual tools; missing companions or controls leave visual verification blocked. For a behavioral or timing decision, observe the thing you are deciding by logging the timing, printing the output, or watching the render. The observation is the test here, not an assertion. Follow the mode's benchmark-checklist gate for measured timing or performance claims. Retain observed output and failures. Denied or unavailable execution blocks empirical claims. Authorized unexecuted sketches may support a reduced design comparison but cannot settle an empirical fork.
6. Present alternatives, tradeoffs, and a recommendation. The output is the decision plus the throwaway artifact, not shippable code. Hand the chosen direction to [Feature](feature.md), or [architect](../../architect/SKILL.md) for the shape, for the real build. Read the complete routed workflow before dependent work. A handoff does not authorize production edits, commits, external writes or delivery. The mode's Opening a PR route requires the complete `opening-a-pr.md` playbook in this directory and explicit external authorization. If unavailable, disclose that deferred dependency and stop PR-dependent work.

Reply with the variants explored, evidence, screenshots for a visual decision or observed output or timing for a behavioral one, tradeoffs, your recommendation, and the actual scratch path. Say plainly that the prototype is throwaway. Disclose unavailable tools, denied operations, untested assumptions and unresolved decisions beside affected claims. If writes are denied, return labelled sketches and no invented scratch artifact.
