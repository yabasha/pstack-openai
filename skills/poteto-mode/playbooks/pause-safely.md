### Pause safely

You own a clean stop. Leave a checkpoint a cold-start agent can resume from. This is explicit only. On "keep going", "going to bed, keep going", or "don't stop", do not pause. Continue only within existing authorization and permissions.

Read [poteto-mode](../SKILL.md) in full. Use [session capabilities](../../../references/host-capabilities.md) and the [assignment contract](../../../references/orchestration-contract.md) for worker control, persistence and interrupted actions. Preserve the active [workflow owner](../../../references/workflow-ownership.md).

1. Stop at a safe boundary. Finish the current atomic step or back out of it within authorized scope. Start nothing new, and cancel any nested subagents through the exposed stop binding. Preserve each worker identity, assignment, exact input revision, output path and available result. Inspect the terminal state and quarantine partial artifacts from integration. A stop request is not proof of termination. If stop or terminal inspection is unavailable, denied or inconclusive, record the worker as unresolved. Do not start a competing writer or transfer its owned path until termination and ownership resolution are observed.
2. Take no irreversible action to pause. No PR and no push unless you already had one out. An existing PR or push does not grant new permission. Preserve all external-action gates. For an interrupted side effect, retain its stable identity, destination, permission and last observed outcome. Inspect prior action records and the destination before deciding whether it completed. Unknown completion blocks automatic replay. Recovery requires explicit authorization and an observed safe idempotency mechanism. Preserve evidence of completed actions instead of repeating them.
3. Make the work durable. Commit uncommitted owned edits as one clear `wip:` commit on the current branch only when commits are authorized and the active owner's review gates are satisfied. Preserve concurrent edits and worker outputs. If the tree is broken, say so in the commit body in one line. Verify the resulting commit and working tree before reporting them. When a commit is unavailable or gated, retain edits on disk and record their exact paths, revision and dirty state as reduced capability. Do not claim a commit or clean tree. If local writes are denied, do not invent durable preservation.
4. Write the resume note off-context. Capture intent, what you were doing, progress and what is verified, current state, next steps, key files, and gotchas. Include branch and full revision, dirty paths, worker identities and terminal or unresolved states, quarantined outputs, permissions and pending gates, interrupted action identities and outcomes, and the first safe resume action. For the compaction trigger write it to an explicit authorized owned file like `/tmp/<slug>-resume.md`; use a durable owned workspace path when temporary storage may disappear. Read the note back before claiming it saved. If a [show-me-your-work](../../show-me-your-work/SKILL.md) trail exists, point at it instead of duplicating it, retaining that skill's helper, transcript audit and review limits. If persistence is unavailable, return the note inline and disclose that no durable checkpoint exists. A saved note does not prove automatic pickup or cross-session recovery.

Reply with where you are in the loop, what is on disk versus still in your head with paths and no diff dumps, the commits you made and whether the tree is clean, and the first action on resume. Include unresolved worker stops, quarantined outputs and unknown side effects. Preserve the trail's Attention section when applicable. This is a pause, not a final report.
