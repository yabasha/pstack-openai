### Runtime forensics

You own the diagnosis. Instrument the live process, don't theorize from source. The deliverable is a cited diagnosis, not a fix.

Read the complete [poteto mode](../SKILL.md), [session capabilities](../../../references/host-capabilities.md), [model roles](../../../references/model-roles.md), [assignment contract](../../../references/orchestration-contract.md) and [poteto role prompt](../../../references/agent-prompts/poteto-agent.md). Discover the matching control-cli or control-ui companion and actual exposed capture, artifact-access and live instrumentation operations. Record successful operations separately from exposed tools. Do not install controls or profilers implicitly. Missing required reads stop dependent work.

1. Capture the live signal on the matching surface via the control skill. Use a CPU profile for a spinning process, a heap snapshot for a leak, or a CDP trace for a visual glitch. Retain the real artifact and identify the observed process, workload and capture context. Source inspection does not replace runtime evidence. Missing controls, denied execution or inaccessible telemetry block new capture. Authorized inspection of a supplied trace is reduced capability and does not prove live capture or live mechanism confirmation.
2. Reduce the artifact to the function on the hot path, the retainer chain from the leaked object to a GC root, or the loop firing without input. Parse large artifacts in an authorized independent worker under the complete [guard-the-context-window](../../principle-guard-the-context-window/SKILL.md) contract. Supply the full poteto prompt, exact input revision and distinct owned output. Inspect the returned finding and cite the original artifact locations that support it. Keep only the reduced finding in the main thread. Use inherited model roles unless supported selection is observed; record requested and actual values separately. Without authorized workers, use bounded sequential parsing as reduced capability and leave independence unmet. Inaccessible artifacts stay unread and unverified.
3. Prove the mechanism before believing it. Inject instrumentation via an exposed CDP eval operation on the running process, or hotfix the live code without reloading, only with authorization and the matching live controls. Record the intervention and observed result against the captured symptom. These diagnostic interventions are mutations despite the read-only deliverable; read-only permission does not authorize them. Without authorized live intervention, keep the proposed mechanism provisional and the proof gate blocked. A source hypothesis or supplied trace alone is not live confirmation.
4. Map the finding back to source. Cite the file, symbol and line that allocates or schedules, alongside the runtime artifact evidence. If source mapping is unavailable, state that gap instead of inventing a location.
5. Throughput checkpoint stays one line: `throughput checkpoint: n/a, read-only forensics`.

Reply with the signal captured, the reduced finding, how you proved the mechanism, the source location and artifact paths. Cite only accessible evidence and distinguish observed findings from provisional hypotheses and absent telemetry. No fix unless asked. Hand back to [Bug fix](bug-fix.md) or [Perf issue](perf-issue.md) once the cause is known; diagnosis does not authorize implementation.
