### Refactoring

Read the complete [mode](../SKILL.md) and each applied principle leaf before acting. Copy all eight steps verbatim into the available todo list, or an authorized local checklist with a disclosed reduced binding, before task-specific items. Discover [session capabilities](../../../references/host-capabilities.md), follow [model roles](../../../references/model-roles.md) and the [assignment contract](../../../references/orchestration-contract.md). Missing required reads or operations stop dependent work. Preserve the mode's companion, comments and matching-control gates.

**You own the contract. The structure changes. The behavior does not.** Distinct from Feature, which adds behavior, and Bug fix, which corrects it.

If the cleanup reveals a missing feature or a real bug, split it out and ship the structural change first against the pinned contract. A redesign is allowed, but name it and route to Feature. Large or cross-cutting structural work belongs to the [figure-it-out](../../figure-it-out/SKILL.md) skill. This playbook is the focused-to-medium change.

1. Pin the behavior contract first. Run the [how](../../how/SKILL.md) skill over the affected subsystem to learn the contract, then write a characterization test, snapshot, or equivalence harness that captures current behavior before any structure moves. If the area has no coverage, write the pin before touching structure. Type check and lint are not a pin.
2. Name the structure the code is missing per [principle-model-the-domain](../../principle-model-the-domain/SKILL.md). Boring code stays when the shape is already clear and local. The reshape must delete branches or invalid states, not add indirection.
3. Name the target shape. State what the module layout, types, and call graph should be if built today ([principle-foundational-thinking](../../principle-foundational-thinking/SKILL.md), [principle-redesign-from-first-principles](../../principle-redesign-from-first-principles/SKILL.md)). If the target crosses a function boundary, run the [architect](../../architect/SKILL.md) skill for parallel design exploration of the shape before the move.
4. Subtract before you add. Delete dead code, collapse one-caller wrappers, drop redundant validators, and remove orphan references before introducing the new shape ([principle-subtract-before-you-add](../../principle-subtract-before-you-add/SKILL.md)). The smallest change that reaches the target shape ships ([principle-laziness-protocol](../../principle-laziness-protocol/SKILL.md)). A speculative cleanup that "might help" gets reverted.
5. Move in small behavior-preserving steps, each keeping the pin green. For API reshapes, migrate every caller and delete the old API in the same wave ([principle-migrate-callers-then-delete-legacy-apis](../../principle-migrate-callers-then-delete-legacy-apis/SKILL.md)). No compatibility shims, no parallel old-and-new paths. Spot-check every rename against the actual files. Renames silently miss usages in strings, prose, and back-references. Delegate the mechanical edits to an authorized independent worker with a specific scope, including file paths, the names being moved and the behavior to hold. Supply the complete [poteto role prompt](../../../references/agent-prompts/poteto-agent.md) and record the exact input revision, owned output paths, worker identity and inspected artifacts. Use inherited model and effort unless a supported configured refactoring selection is observed. Record requested and actual selections separately; unknown actual models prove no diversity. Review the returned diff yourself. When workers are unavailable or unauthorized, perform authorized mechanical edits sequentially only as reduced capability and leave the independent delegation gate unsatisfied.
6. Prove behavior is unchanged on the real artifact, not "it compiles" ([principle-prove-it-works](../../principle-prove-it-works/SKILL.md)). For larger reshapes, run an equivalence check: a script that diffs old-vs-new outputs, a recorded baseline replayed against the new code, or a smoke run on the matching surface via the relevant control skill.
7. Confirm the change is worth keeping. The success measure is reduced reader load ([principle-minimize-reader-load](../../principle-minimize-reader-load/SKILL.md)). If the diff does not lower reader load somewhere, revert it.
8. Rebase into small ordered commits. A subtraction commit, then the reshape, then any follow-on cleanup. Shape them with the [sequence-verifiable-units](../../principle-sequence-verifiable-units/SKILL.md) principle skill, so each behavior-preserving slice stays green before the next. Rebase and commit only with authorization and an available operation, preserving concurrent work. Otherwise return the checked local diff and ordered delivery plan with these operations unperformed. Run **Opening a PR** by reading `skills/poteto-mode/playbooks/opening-a-pr.md` in full and following its complete contract when available and authorized. This is a deferred task 21 dependency for task 24 integration until that file exists; stop PR-dependent work if absent. No push or PR creation follows from this playbook without explicit authorization. Opening a PR never starts Babysit implicitly.

**Reply:** the structure that changed, the pin you held it against, the equivalence proof, the reader-load delta, what shipped and what got reverted. No new behavior.

If writes or execution are unavailable, return a source-grounded proposal and identify the unperformed pin, edits or equivalence checks. Missing behavior evidence blocks unchanged-behavior claims. Structural validation, type checks, lint and a worker self-report never prove equivalence. Report each missing capability and denied gate alongside the partial artifacts.
