### Feature

You own the design. Plan, review, verify. Delegate implementation. Stay in the lead.

Read [poteto-mode](../SKILL.md) in full before work. Follow its Comments rules and required companion gates. Discover authorized operations through [session capabilities](../../../references/host-capabilities.md). Use [assignment and integration](../../../references/orchestration-contract.md) and [model roles](../../../references/model-roles.md). Keep the playbook steps verbatim in an exposed todo list, or an authorized local checklist with the reduced binding disclosed. Invocation aliases name workflows, not registered host commands.

1. Run [how](../../how/SKILL.md) over the affected subsystem. Ground the intended user outcome in traced source and caller behavior.
2. Run [architect](../../architect/SKILL.md) for parallel design exploration. Follow its complete design and arena contracts. Preserve sequential alternatives only as reduced capability when independent workers are unavailable. Required independence remains blocked.
3. Write the throughput checkpoint as four todo items. Keep any dimension that does not apply, such as a single file or no fan-out, with `n/a: <reason>` rather than dropping it.
   - Blocking first steps. Gates run before fan-out.
   - Independent workstreams. Disjoint files, services, or layers parallelize. Shared writes serialize.
   - Shared mutable state. Default to splitting the target using [separate-before-serializing-shared-state](../../principle-separate-before-serializing-shared-state/SKILL.md). Serialize only for real invariants.
   - Smallest safe decomposition. If one worker is best, name why.
4. Delegate code-writing to a fresh independent worker with the entire [poteto role prompt](../../../references/agent-prompts/poteto-agent.md) and exact file pointers. Use the configured feature role when supported and observed. Otherwise request inherited model and effort. Record requested and observed selections separately, with unknown for unobserved values. Assign exact file paths, a named data shape and its organizing structure, and success criteria tied to the user outcome. Choose the structure before the delegate writes logic under [model-the-domain](../../principle-model-the-domain/SKILL.md). Prefer a state machine over scattered booleans, a table or registry over branching, or a typed model over repeated shape assumptions. When implementation admits multiple valid shapes, such as error handling, abstraction layer or test structure, delegate through [arena](../../arena/SKILL.md). Its runners surface alternatives and its fresh cross-judge guards the pick. This gate is mandatory. There is no skip-with-reason escape, and Laziness Protocol does not override it. The gain is review separation, not lines saved. A worker forbidden to spawn owns the diff directly and returns it to the lead for the same review separation. It never waits on a nested worker or replies "standing by". Without authorized independent workers, direct implementation can be an explicit reduced result, but it does not satisfy independent review separation. The lead reviews the actual diff and owns the summary. Apply the mode's Comments rules. Make surgical edits and re-ground upstream-derived files against their source. Port shared-primitive improvements to all consumers and verify each. Commit each verified unit when authorized and after the mode's commit gates.
5. Verify on the matching surface using available authorized control tools and the mode's matching companion requirements. Tie observed evidence to the intended user outcome. "Inconclusive" or wrong-surface is not a pass. Flag it and retain the unverified gate. Compilation or structural checks do not prove the feature works.
6. Rebase into small, ordered commits and stack follow-ups when authorized and safe for concurrent work. Use [sequence-verifiable-units](../../principle-sequence-verifiable-units/SKILL.md). Build, verify and commit each small unit before the next. An unrun required check blocks advancement. If commit or rebase is unavailable or unauthorized, return the checked diff and ordered delivery plan with those operations unperformed.
7. If the design is contested, run [interrogate](../../interrogate/SKILL.md) before shipping. Preserve its review rubric, independence and observed model-diversity limits. Sequential review does not become independent or multi-model review.
8. Run the Opening a PR playbook at `opening-a-pr.md` in this directory. This caller requires that complete playbook, its review gates and actual PR result inspection. If the file is absent, report the exact deferred dependency and stop PR-dependent work. Do not reconstruct it from this paragraph. External PR creation and push require actual authorization. Return a local reviewable result when those actions are unavailable or unauthorized. Never claim a local draft is a created PR. Opening a PR does not start Babysit.

Code-coupled work, such as one feature or one migration, goes to a single owner with the checkpoint inline. That owner fans out internally after the blocking phase when authorized and supported. Parent-level fan-out is for slices that produce independent artifacts, such as audits, cross-subsystem investigations or competing experiments. Rewrite the checkpoint at phase boundaries. Spawn a fresh owner rather than chaining interrupts. Distinct owned paths and inspected results remain prerequisites for integration.

Reply with what you built, what you chose and why, the throughput checkpoint, and open decisions. Use tables for design alternatives. Name the end user's changed behavior and what the next maintainer inherits. Link observed verification artifacts and actual PRs. Disclose missing companions, unavailable workers, unobserved models, failed checks and deferred dependencies beside the affected claim. Keep incomplete gates visible.
