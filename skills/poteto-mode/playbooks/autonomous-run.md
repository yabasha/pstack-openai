### Autonomous run

Own the exit condition within the authorized scope. Define done, then drive to it while execution is available. This is the playbook for "run until done" and "/loop until X". The source's /loop was a host built-in, not a pstack skill or a portable tool binding.

Read [poteto-mode](../SKILL.md) in full. Discover actual operations through [session capabilities](../../../references/host-capabilities.md) and follow the [assignment contract](../../../references/orchestration-contract.md). Upstream autonomy does not override user gates or host permissions.

1. State the exit condition as a checkable predicate before the first iteration, such as tests green, repro fixed, all N PRs merged or pixel-diff zero. Record the check and its current evidence. A merge predicate does not authorize merging.
2. Pick an exposed, authorized wake mechanism and observe its registration before claiming it active. An event to watch, such as CI, a merge or a ref advancing, gets an independent watcher worker with a long time-based heartbeat as fallback. No event gets a fixed-interval heartbeat sized to when the result is worth re-checking. Use the [poteto role prompt](../../../references/agent-prompts/poteto-agent.md), exact assignment revision and isolated outputs for a watcher. Follow [model roles](../../../references/model-roles.md), defaulting to inherit-parent and recording actual models only when observed. Record missing or failed wake, heartbeat, worker and stop/control bindings separately. Never install or schedule implicitly. If persistent wake is unavailable, continue useful authorized iterations in the current turn and save the continuation brief below before returning. Label this reduced capability, without a promise of work after the turn. A foreground check is not an independent watcher. If control is unavailable, disclose that limit and do not claim a worker stopped or unattended recovery is safe.
3. Each iteration makes the smallest change the evidence justifies and verifies it against the predicate. Commit if it advanced and commit authorization and review gates are satisfied. Otherwise keep the verified change local and report the unmet gate. Discard changes that did not help, reverting only this run's owned changes. Revert speculative fixes that merely "might help". Sequence work through [sequence-verifiable-units](../../principle-sequence-verifiable-units/SKILL.md), verifying each unit before the next instead of batching checks at the end. Missing verification blocks dependent advancement.
4. Address mid-run broken skills, related bugs, flaky verifiers, review noise, tooling failures, orphaned follow-ups and fixable drift through poteto-mode within authorization. Put out-of-band fixes in their own PR when PR creation is authorized, using the mode's Opening a PR route. Otherwise prepare the separate local fix and disclose the unperformed PR action. Do not park authorized reversible work for the human or ask a question an experiment can settle. Surface irreversible actions, explicit operator gates, genuine product or preference calls no experiment can settle, or a real dead end. Stop dependent work on a broken contract, continue independent work, and return to the main predicate after each side fix.
5. Checkpoint every iteration through [show-me-your-work](../../show-me-your-work/SKILL.md), with what changed and whether the predicate moved. Use its [log helper](../../show-me-your-work/scripts/log.sh) through authorized execution with an explicit owned local log path and its [template](../../show-me-your-work/references/decision-log-template.tsv). Keep append-only history, read back saved records, audit against this run's available transcript and preserve its cross-model review and Attention requirements. Missing history, persistence or independent review remains visible. A saved log does not prove unattended execution.
6. Stop successfully only when the predicate is met. A plateau is not completion. Keep going and pivot while authorization and execution permit. Surface a genuine dead end instead of spinning and never relax the predicate to declare victory. A session boundary, unavailable persistent tool or explicit pause requires a handoff with the predicate still open, not a completion claim.

When ongoing work cannot survive the turn, save a continuation brief at an explicit authorized local path and read it back. Include the unchanged exit predicate and current state, iterations completed, current revision and owned changes, verification commands and results, decision-log path, accepted and discarded changes, outstanding gates and missing capabilities, pending action identities and known outcomes, and the next check or experiment. A new run must inspect current state and permissions before continuing or replaying an action. Unknown external outcomes block replay. If local persistence is denied or unavailable, return the brief inline and state that no durable save occurred. Neither form registers a wake mechanism or proves automatic pickup.

Reply with the exit condition, iterations run, what landed, what was discarded and final predicate state. Distinguish verified local work from actual commits, PRs and merges. Link the saved trail and continuation brief only after readback. Report missing capabilities, blocked gates and any unperformed action. Keep show-me-your-work's Attention section when a trail was produced.
