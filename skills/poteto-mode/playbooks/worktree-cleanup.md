### Worktree and simulator cleanup

Reclaim disk space by pruning merged or abandoned Git worktrees and stale iOS simulators. You own the audit and safety gate. Deletion can destroy uncommitted or ignored work, so preserve anything in use, unrelated to this request, or lacking evidence. Follow [Autonomy](../SKILL.md), [session capabilities](../../../references/host-capabilities.md) and the [workflow owner](../../../references/workflow-ownership.md). No audit bucket grants permission to delete user state.

1. Snapshot and audit. Record `df -h /`, then use the existing [read-only audit wrapper](../scripts/worktree-audit.sh) and its [implementation](../scripts/worktree-audit.py), as required by [Build the lever](../../principle-build-the-lever/SKILL.md). Run through Bun without installing dependencies, from the package root:

   ```sh
   bun --no-install -e 'const p=Bun.spawnSync(["bash","skills/poteto-mode/scripts/worktree-audit.sh",...process.argv.slice(1)]);process.stdout.write(p.stdout);process.stderr.write(p.stderr);process.exit(p.exitCode)' -- --repo <repository-path> --base <verified-local-base-ref> --history-map <authorized-history-export.json> --pr-state <authorized-pr-export.json>
   ```

   Paths come from `git worktree list --porcelain -z`, never hand-typed, under [Encode lessons in structure](../../principle-encode-lessons-in-structure/SKILL.md). The helper excludes the primary checkout, returns JSON sorted by logical size in bytes, and reports HEAD age in days, merge state, dirty state, local tracking state, PR records, last-chat timestamp and a suggested bucket. It performs no fetch, forge request, private transcript discovery or deletion. Supply an explicit verified local base. Tracking refs and PR exports may be stale; record their freshness before treating them as evidence. A CLOSED PR is not merge evidence. Ancestry and an explicitly MERGED PR account for different merge methods.

   The optional history export maps complete paths to past Unix timestamps, or null for explicitly known absent history. A missing key is unknown. PR input is an array of `number`, `state` and `headRefName` records; omitted input is unknown, while an explicit empty array says there are no matching exported PRs. Null age, remote, dirty or other evidence means hold, never permission. Logical size is not allocated disk usage. Ignored files are outside Git dirty counts. Retain the raw audit as an artifact. Background a slow authorized history scan only when the host exposes and successfully runs that operation; otherwise disclose sequential reduced capability.

2. The bucket is advice. The pinned and active chats are the real usage artifact under [Prove it works](../../principle-prove-it-works/SKILL.md). Get that set from the user or an exposed, authorized sidebar/history operation and cross-check every candidate. A `review-merged` row still needs this check. Preserve the primary and current checkout, unrelated worktrees, and every pinned or active chat's worktree. Missing sidebar, history, ownership or freshness evidence holds the candidate.

3. Verify usage before deleting. For `verify-recent-chat` rows and anything in doubt, use authorized read-only workers to inspect the relevant accessible transcripts and report pinned or ongoing chats and every worktree they touch. Follow [Guard the context window](../../principle-guard-the-context-window/SKILL.md), the [poteto prompt](../../../references/agent-prompts/poteto-agent.md), [model roles](../../../references/model-roles.md) and the [assignment contract](../../../references/orchestration-contract.md). Retain worker identities, revision and inspected results. Pinned chats may use sibling arena or reproduction worktrees absent from the sidebar. Without authorized independent workers, inspect bounded evidence sequentially and label reduced capability. Without the needed transcripts or user confirmation, hold the path. An export's last timestamp alone does not prove absence of live usage.

4. Pause on irreversible loss. `wip:N` counts tracked changes; show the diff and get a decision. `scratch:N` counts untracked files, not proof they are disposable. Name those files and obtain a decision before discarding them. Inspect ignored build artifacts and other ignored user state separately. Unknown dirty state, age or tracking evidence holds the path. Clean, merged and not-in-use paths are candidates only within the recorded cleanup scope and after the applicable user deletion gate. Record each exact Git-listed path, HEAD, usage evidence, merge evidence, files at risk, intended action and explicit authorization. Upstream autonomy does not waive this gate.

5. Prune only the confirmed set. Re-list worktrees and recheck HEAD, status, ignored state and usage immediately before removal. A changed path, new usage or unknown outcome blocks the action. For an authorized exact path, `git worktree remove --force <path>` is the source removal operation. If ignored artifacts leave the directory behind, inspect the remainder and obtain authorization for that exact directory before `rm -rf <path>`. Never widen the path or delete an unrelated directory. Run `git worktree prune` only within the authorized repository cleanup. Branch refs survive normal worktree removal, but that does not recover discarded uncommitted or ignored files. Confirm each result with a fresh list and `df -h /`; after interruption inspect the recorded action and destination before any retry.

6. Simulators and other reclaimers. Discover local macOS/Xcode tools and identify in-use devices first. The source operations are `xcrun simctl --set testing delete all` for XCTestDevices clones, `xcrun simctl delete unavailable`, and `xcrun simctl runtime list` followed by `xcrun simctl runtime delete <id>` for an approved old runtime. These delete user state. Show the exact targets and get the applicable deletion authorization before execution. If tools are absent or execution is denied, report this portion blocked. Other candidates include Xcode DerivedData and iOS DeviceSupport, the source editor's application-support database backups and workspace snapshots, and pnpm, uv, brew or yarn caches. Discover actual host paths rather than assume a source-editor data location. Clear only named caches within authorization that the user has not said to keep. Do not infer abandonment from size or age.

The gates above are the review for this playbook. If deletion is unauthorized, produce the audit and held-candidate report as reduced capability. If even the required reads or execution are unavailable, report the missing binding and blocked audit. Never claim reclaimed space from proposed commands.

Reply with `df -h /` before and after, measured space reclaimed, worktrees actually pruned, and a one-line reason for each held path, including the chat using it or the files at risk. Keep unavailable measurements explicit. If nothing was removed, say so and distinguish the audit from completed cleanup.
