# Statechart execution

Use an authorized scratch folder outside the product checkout. Copy the model, configuration, any local TLA+ modules and reviewed executable view there. Record their hashes, source revision and exclusions. Use a unique owned output folder for every run. The helper copies sibling regular .tla modules into its private scratch input directory; external module dependencies remain explicit reviewed inputs. Before execution it snapshots and hashes every local TLA+ module, model, config and view. It records those executed bytes in input-manifest.json. Never overwrite user files or share output folders.

Run helpers through Bun. JAVA and TLA2TOOLS must be absolute paths to a separately reviewed local Java executable and tla2tools.jar. Java 11 or later is required. Record versions and jar digest. No helper or test installs tools or accesses a package manager. Missing dependencies block execution, with model/chart drafts explicitly unverified.

A view is executable JavaScript or TypeScript, including its imports. The port requires a self-contained view with static node: builtin imports only. Relative, package, dynamic import and require calls are rejected; bundle their reviewed code into the view before execution. Review it before --view and use available isolation. Its state(vars) returns a string for flat charts, an array for parents, or an object for regions. TLA+ sequences have one-based object keys, and sets are arrays. Views execute in the helper worker with its permissions; a subprocess is not a security sandbox.

Each subprocess has a 120-second deadline, 16 MiB combined output bound, one TLC worker and 512 MiB Java heap. The parent has a 300-second whole-run deadline. Expiry exits 2 as incomplete and publishes no output; external SIGINT/SIGTERM remain 130/143. Timeouts, output limits and resource errors are incomplete. Cancellation kills the detached worker group; the janitor kills it if the parent disappears. Inspect surviving processes and quarantine partial artifacts after interruption. Preserve stderr in a task-owned command log because unsuccessful runs do not publish output folders.

The CLI is bun scripts/statechart.ts SPEC.tla --config FILE --view FILE --out NEWDIR. Exit 0 means every configured rule held in the original TLC run, 1 means a rule broke, 2 means an error, 130/143 mean interruption. Only 0/1 publish output. Read report.md and tlc.out, including Rules not checked, graph limitations and each separately retained tlc-RULE.out. The initial result can survive a later incomplete rule check; it never proves unchecked rules. Followup rule checks stop at 100,000 states.

Deadlock is checked by default. Model intentional terminal states with explicit stuttering actions, or document an intentional CHECK_DEADLOCK FALSE config. The chart budget is 500 states. Larger graphs show bug paths only, or omit chart.mmd when no rule breaks.

The compiler retires from-chart, --against, --fixed, --expect-broken, integrated --png, summary.json and stories.md. To compare models, run each separately with its own reviewed config/view and unique outputs, then compare their reports with stated scope. There is no automatic equivalence or expected-failure pass. Render SVG separately with the approved local renderer in render.md. Missing renderer or image inspection leaves visual completion blocked.

ChatGPT and Codex each require actual filesystem, execution, persistence and image observations. Local helper tests do not prove plugin discovery or loading on either host. Reproduce each bug through real user/client entry points before claiming a product bug or fix. Explain exclusions and unchecked rules.
