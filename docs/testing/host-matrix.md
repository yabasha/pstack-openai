# Shared host workflow matrix

This is a test procedure and capability contract, not observed host evidence. Both ChatGPT and Codex remain not-run. Direct file access, supplied documentation, structural tests and pictures do not establish supported host loading.

Read [capabilities](../../references/host-capabilities.md), [ownership](../../references/workflow-ownership.md), [assignments](../../references/orchestration-contract.md) and [models](../../references/model-roles.md). Use one shared skill tree. Do not fork skills by host.

| Session or condition | Full expectation | Reduced branch | Blocked branch |
| --- | --- | --- | --- |
| Ordinary ChatGPT without execution | Complete supplied-text reasoning can pass with native input, response and reviewed outcome evidence; required tools still need actual observations. | A proposal with omitted runtime or independent-work requirements remains reduced. | Runnable proof, app driving and dependency-backed helpers remain blocked without execution. |
| Worker-enabled ChatGPT | Observe spawn, worker identity, exact revision, isolated output and result inspection. | Sequential authorized roles when independent workers are absent. | Independent review, diversity and standing programs cannot pass from sequential work. |
| Local Codex | Observe repository reads, scoped writes and command results separately. | Local artifacts with absent external delivery or persistent wake disclosed. | Supported plugin loading and invocation remain unverified until tested through their actual host mechanism. |
| Absent GitHub access | Requires actual forge access, dependency prerequisites and permitted actions. | Prepare local PR content or recommendations. | No PR creation, live watcher verdict or merge claim. |
| Optional setup skipped | A verified saved model override requires supported persistence, authorization and readback. | Use inherited session role choices and optional verification offer may be declined. | Missing dependencies keep dependent helpers setup-required. No implicit installation or enabling. |

The full branch never follows from a host name. Unknown actual model and effort values remain unknown. Requested model diversity does not prove observed diversity. Bind tool identifiers from the current exposed interface rather than inventing portable APIs. Keep denied operations and failed observations in evidence.

Supported loading is a separate acceptance check. Record the exact approved package revision, actual host loading or enabling operation, discovery result and workflow invocation. Read an installed file only as a file-read observation. Loading is not proven by a manifest, package path or documentation example.

For each [guide case](../parity/cases/guides.json), record the required observations, permissions, actual output and existing artifacts under the [evidence schema](../parity/evidence.schema.json). Applicability belongs to the coordinator-owned registry. A case definition or scoped structural pass does not alter host status. Preserve full expectations beside reduced and blocked results.

Run setup and overnight cases with missing execution, workers, wake, stop, history and persistence separately. Without persistent wake, perform useful authorized work in the current turn and return a read-back continuation brief, or an inline brief if persistence is absent. Promise no work after the turn. A saved log does not prove automatic recovery. Inspect interrupted action identity and destination before replay; an unknown outcome blocks it.

Dependency setup, plugin installation, host enabling, personal settings, schedules, external writes and credentials need their own explicit grants.
