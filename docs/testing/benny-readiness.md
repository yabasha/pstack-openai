## Separate live authorization

Copying or refreshing the pack in another repository, installing or enabling a plugin, changing host settings, committing files, starting disposable UI checks, sending test reports, creating or updating automations, enabling traffic, filing or updating tracker tickets, compensating tickets, and opening draft PRs require authorization for their actual scope. Readiness evidence and configuration values do not grant it. Never expose tokens to workers or save secrets in the pack.

Prepare triage first, complete its reviewed draft and supported host editor/save handoff, then prepare repro. Existing automations use an authorized update capability or user editor checklist; create no duplicates. Both live prompts must read their exact committed operational file directly. Cache paths and copied operational excerpts are unsuitable.

After explicit live test authorization, observe the setup file's seven thread-safety checks and the control contract's nine adapter checks. Verify one triage verdict and marker, trusted marker identity, immutable source coordinates, worker write exclusion, no source root post, and no writes after failed parent preflight. Missing coordinates, deleted parent, duplicate report, ownership, existing fix, untrusted marker and unsupported trigger must take the declared safe outcome. Every claimed UI repro needs the discriminating symptom twice, reset, screenshot, recording and state cross-check. Existing fixes need matching baseline and patched evidence without competing code.

Treat interrupted writes with unknown outcomes as blocked replay until the action identity and destination have been inspected. New ticket creation requires available and authorized compensation before any write. Enable traffic only after observed authorized tests and an explicit enable decision. Do not claim success from these instructions, fixture review, source inspection or structural validation.
