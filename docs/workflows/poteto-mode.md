# Poteto mode walkthrough

Start with an authorized read-only question about a disposable source fixture and a named active controller. The example prompt is: "Use Poteto mode to explain this fixture's state ownership. Stay read-only and disclose missing independent workers."

Read the entire [mode](../../skills/poteto-mode/SKILL.md), selected [Investigation playbook](../../skills/poteto-mode/playbooks/investigation.md), routed [how](../../skills/how/SKILL.md) instructions and their required prompts. Read every applied principle leaf in full. The [24-principle catalog](../principles/README.md) helps locate leaves and does not replace those reads.

1. Resolve [workflow ownership](../../references/workflow-ownership.md). An explicit pstack invocation owns this workflow. An existing Superpowers controller remains owner for an unqualified follow-up. If both are explicitly requested, settle ownership before dispatch or writes. Metadata does not register a host mode or icon.
2. Match the read-only question to Investigation. Copy its exact steps into an exposed todo tool or authorized local checklist with disclosed reduced binding. Keep explicit skip reasons. Its checkpoint is `throughput checkpoint: n/a, read-only investigation`.
3. Discover actual [capabilities](../../references/host-capabilities.md). Route through how, and through [why](../../skills/why/SKILL.md) for motivation. Read required prompts and source contracts. Keep workers read-only and inspect their results before relying on them. Missing workers permit disclosed sequential roles. Source access gaps remain explicit.
4. Explain Overview, Key Concepts, How It Works, Where Things Live and Gotchas as how permits. Use a tradeoffs table for a choice. Preserve why confidence tiers and unknowns for motivation. Cite inspected files and name only principles actually read and the decision each changed.
5. Apply [unslop](../../skills/unslop/SKILL.md) and return evidence and limits. Investigation ends with an answer. No PR or babysit follows; a later code change needs a separately authorized reroute.

For other tasks, the mode retains all 23 routes. Read the full selected playbook before work. Nontrivial implementation records blocking first steps, independent workstreams, shared mutable state and smallest safe decomposition, with reasons for n/a. A no-spawn delegate owns its scoped diff and returns it to the lead; required independent lead review remains a gate.

Read actual helper contracts before use. [Helper setup](../testing/helper-setup.md) blocks dependency-backed execution when metadata is missing. Orch needs an explicit outside-package store and does not spawn workers or enforce verification precedence. Watch-pr needs full heads, finite carried budgets and inspected event kind, terminal and reason. Status-only exit 0 and queued WAITING do not prove merge. Check-plan accepts one plan path and proves format only. Decision logs need an owned path and six exact positional fields with readback. Cleanup audit buckets authorize no deletion. See the mode's complete bindings and [maintenance sequence](../maintenance/upstream-updates.md).

Expected visible result is a cited read-only explanation with routing, checkpoint and capability limits. Missing mode, playbook or applied leaf blocks dependent work. Missing independent review or companion deslop, create-skill or control tools remains a gate. Local source availability and the tested helper snapshot establish no host pass.
