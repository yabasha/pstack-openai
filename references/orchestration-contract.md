# Assignment and integration contract

Before dispatch, the coordinator creates an immutable assignment with `id`, `scope`, `inputRevision`, `outputOwner`, `isolatedOutputPath`, `role`, `retryCount`, `terminalStatus`, and `evidenceLinks`. Use the full Git SHA for inputRevision, an exact owned path, and an explicit role. Start retryCount at 0 and terminalStatus at `pending`. Preserve every attempt as an append-only event under the same assignment ID; update status through events, never rewrite the original scope, revision, owner or path. A changed scope or revision requires a new assignment ID that links its predecessor.

The coordinator checks authorization and observed host bindings before dispatch. One path has one writer. Reject overlapping paths before work starts; assign distinct paths instead. Workers write only their isolated output and report results. Only the coordinator integrates shared files, inventory, registry, or other workers' output.

Accept a result only when its assignment identity and input SHA match, its artifacts exist, and required method evidence was observed. Reject stale revisions. Permit at most one retry for missing required SHA or method evidence, after inspecting the prior attempt and confirming the same permissions still apply. A retry count of 1 exhausts this allowance. Denied permissions, unknown action outcomes, and missing artifacts never become success by retry policy.

Terminal states are `completed`, `blocked`, `failed`, and `cancelled`. A completion event links the exact result and evidence. Stop a cancelled worker through the exposed stop binding when available, then inspect its terminal state. Quarantine any partial artifacts; cancellation does not authorize their integration. If stop cannot be observed, record that limit and do not claim termination. Report interrupted execution explicitly.

Before an external action, record explicit permission, a stable action identity, the intended destination and the last observed outcome. After interruption, inspect whether that identity already completed. Retry only with authorization, an observed safe replay decision and an idempotency mechanism appropriate to the destination. If the outcome is unknown, block replay. Do not infer permission from upstream autonomy instructions.

History and persistence have separate bindings. Keep assignment events and result links in an authorized durable location and verify readback. If unavailable, declare the gap and offer an authorized local handoff as reduced capability; never claim unattended recovery or cross-session continuity. All host statuses remain `not-run` until actual observations exist.

## Structured Arena and Swarm receipts

A method receipt is JSON with schemaVersion 1, kind `arena` or `swarm`, inputRevision, assignments, reviewArtifact, reviewedBy and declaredOrder. The inputRevision is the actual task repository revision, distinct from the packageCommit identifying these instructions. It must match the evidence record. The declared order precedes every dispatch. reviewArtifact records the qualitative outcome review and reviewedBy identifies its reviewer. All referenced artifacts must exist and be listed in the evidence record.

Each assignment records id, workerId, inputRevision, outputOwner, outputPath, role, status, startedOrder, completedOrder, requestedModel, actualModel, retryCount, method, taskArtifact, rubricProvided, resultRevision, resultMethod and outputSha256. Result revision and method must match the assignment, and the inspected output bytes must match their digest. Worker and assignment identities are distinct. outputOwner equals workerId; output directories do not overlap. Integer order values record the observed dispatch and completion sequence, not estimated time. The method has positive sampleCount, sampleDefinition and order. Missing model observations use unknown. The validator requires assignment-bound spawn and result inspection, and isolated-write for output-producing candidates. A read-only judge may return its result through the coordinator's authorized artifact capture. A cancelled result needs bound stop, terminal inspection and quarantine observations. No operation string alone establishes a method.

Arena adds candidates, judge, rubricArtifact and synthesis. At least two candidates share the same taskArtifact, finish before a distinct fresh judge starts and do not receive the parent rubric. Synthesis has order, inspectedCandidates, artifact and verificationArtifact; it follows completed judgment and accounts for every candidate. The review artifact assesses scoring, base selection, grafts, rejections and verification quality. File presence and phase ordering do not establish the quality of those decisions.

Swarm adds partition, race, cancelled and quarantined. Partition declares requiredSlices, results mapping each slice to its assignment, and gaps. A full coverage claim requires all slices with completed inspected outputs; gaps remain explicit reduced or blocked work. Race declares rule, assignments, winner and ruleArtifact. first-pass must select the first completed survivor; rank-all needs all results; best-of retains an explicit reviewed selection. Cancelled assignments must be quarantined and cannot enter the aggregate. The combined partition-and-race case requires both methods and its cancellation exercise. The partition walkthrough exercises only its declared slices; it does not acquire an unrelated race requirement.

The three-file Swarm walkthrough requires exactly three declared slices and three completed results. Its partition-only receipt uses race null and empty cancellation, quarantine and failureExercises arrays. The combined case also records failureExercises. Each event has assignmentId, kind, attempt, order, reason and evidence, with bound result-rejection or terminal inspection. Rejected missing-revision or missing-method evidence uses attempts 0 then 1; a second invalid result exhausts the retry and leaves a failed or blocked assignment. A separate failed or blocked dropout is disclosed. These failed outputs cannot satisfy required coverage. The final assignment result metadata records the inspected terminal summary; rejection-event artifacts retain the invalid attempts.
