# Assignment and integration contract

Before substantive dispatch, bootstrap a worker only to observe its canonical actual worker ID and readiness. Bootstrap grants no source reads, task execution or task output. Then create an immutable assignment with `id`, `scope`, `inputRevision`, `outputOwner`, `isolatedOutputPath`, `role`, `retryCount`, `terminalStatus`, and `evidenceLinks`. Use that observed identity as outputOwner, the full Git SHA for inputRevision, an exact owned path, and an explicit role. Start retryCount at 0 and terminalStatus at `pending`. Preserve every attempt as an append-only event under the same assignment ID; update status through events, never rewrite the original scope, revision, owner or path. A changed scope or revision requires a new assignment ID that links its predecessor.

The coordinator checks authorization and observed host bindings before dispatch. One path has one writer. Reject overlapping paths before work starts; assign distinct paths instead. Workers write only their isolated output and report results. Only the coordinator integrates shared files, inventory, registry, or other workers' output.

Accept a result only when its assignment identity and input SHA match, its artifacts exist, and required method evidence was observed. Reject stale revisions. For omitted required SHA or method reporting, permit one metadata-only correction from the same worker as a continuation of result inspection. First capture the raw return in a coordinator-owned append-only file, inspect it and confirm the same permissions still apply. The correction may report only evidence supported by the already-completed attempt. It must not rerun execution, mutate output bytes, reconstruct an unobserved method, or change assignment identity, revision, method, owner or output path. Capture the second raw return separately. A second miss exhausts retryCount 1 and leaves the assignment failed or blocked with a gap. An unavailable worker or unsupported evidence also leaves a gap. New substantive execution requires a fresh worker with a linked immutable assignment, distinct owner and output path. Never transfer old ownership or relabel an assignment to reset its reporting allowance. Denied permissions, unknown action outcomes, missing artifacts and stale revisions never become success by this correction policy.

Terminal states are `completed`, `blocked`, `failed`, and `cancelled`. A completion event links the exact result and evidence. Stop a cancelled worker through the exposed stop binding when available, then inspect its terminal state. Quarantine any partial artifacts; cancellation does not authorize their integration. If stop cannot be observed, record that limit and do not claim termination. Report interrupted execution explicitly.

Before an external action, record explicit permission, a stable action identity, the intended destination and the last observed outcome. After interruption, inspect whether that identity already completed. Retry only with authorization, an observed safe replay decision and an idempotency mechanism appropriate to the destination. If the outcome is unknown, block replay. Do not infer permission from upstream autonomy instructions.

History and persistence have separate bindings. Keep assignment events and result links in an authorized durable location and verify readback. If unavailable, declare the gap and offer an authorized local handoff as reduced capability; never claim unattended recovery or cross-session continuity. All host statuses remain `not-run` until actual observations exist.

## Structured Arena and Swarm receipts

A method receipt is JSON with schemaVersion 1, kind `arena` or `swarm`, inputRevision, assignments, reviewArtifact, reviewedBy and declaredOrder. The inputRevision is the actual task repository revision, distinct from the packageCommit identifying these instructions. It must match the evidence record. The declared order precedes every dispatch. reviewArtifact records the qualitative outcome review and reviewedBy identifies its reviewer. All referenced artifacts must exist and be listed in the evidence record.

The receipt has exactly the common keys above plus its kind-specific keys below. Each assignment has exactly id, workerId, inputRevision, outputOwner, outputPath, role, status, startedOrder, completedOrder, requestedModel, actualModel, retryCount, method, taskArtifact, rubricProvided, resultRevision, resultMethod and outputSha256. Result revision must match the assignment. method is an object with exactly three fields. sampleCount is a positive integer, and sampleDefinition and order are nonempty strings. resultMethod is an object equal to the assigned method, not a prose description. The inspected output bytes must match outputSha256. outputPath names the result file, not its directory. Worker and assignment identities are distinct. outputOwner equals the canonical actual workerId; output directories do not overlap. declaredOrder, startedOrder, completedOrder and retryCount are integers. Order values record observed sequence, not estimated time. Missing model observations use unknown. The validator requires assignment-bound spawn and result inspection, and isolated-write for output-producing candidates. A read-only judge may return its result through the coordinator's authorized artifact capture. A cancelled result needs bound stop, terminal inspection and quarantine observations. No operation string alone establishes a method.

Arena adds candidates, judge, rubricArtifact and synthesis. At least two candidates share the same taskArtifact, finish before a distinct fresh judge starts and do not receive the parent rubric. Synthesis has order, inspectedCandidates, artifact and verificationArtifact; it follows completed judgment and accounts for every candidate. The review artifact assesses scoring, base selection, grafts, rejections and verification quality. File presence and phase ordering do not establish the quality of those decisions.

Swarm adds partition, race, cancelled and quarantined. Partition declares requiredSlices, results mapping each slice to its assignment, and gaps. A full coverage claim requires all slices with completed inspected outputs; gaps remain explicit reduced or blocked work. Race declares rule, assignments, winner and ruleArtifact. first-pass must select the first completed survivor; rank-all needs all results; best-of retains an explicit reviewed selection. Cancelled assignments must be quarantined and cannot enter the aggregate. The combined partition-and-race case requires both methods and its cancellation exercise. The partition walkthrough exercises only its declared slices; it does not acquire an unrelated race requirement.

The three-file Swarm walkthrough requires exactly three declared slices and three completed results. Its partition-only receipt uses race null and empty cancellation, quarantine and failureExercises arrays. The combined case also records failureExercises. Each event has exactly assignmentId, kind, attempt, order, reason and evidence, with bound result-rejection or terminal inspection. attempt and order are integers. Rejected missing-revision or missing-method reporting uses attempts 0 then 1 for the same worker's bounded inspection correction; a second invalid result exhausts the allowance and leaves a failed or blocked assignment. A separate failed or blocked dropout has a different assignment ID from every rejected assignment. These failed outputs cannot satisfy required coverage. The final assignment result metadata records the inspected terminal summary. Each rejection-event artifact is a separate coordinator-owned raw return, captured before inspection and retained append-only. Its resolved path differs from every other rejected-attempt artifact and every assignment's final output file. Equal bytes in separate captures are legitimate and do not require different content hashes. Valid terminal-summary metadata does not repair or erase the rejected historical returns.

## Arena model-family receipt

A full Arena method receipt includes modelFamilyEvidence with exactly parentModel, parentFamily, judgeModel, judgeFamily and evidence. Evidence names an inspected listed artifact recording the exposed model identities and the family mapping source. Bind judgeModel to the judge assignment's actualModel. Record explicit observed models and different families; unknown, unavailable, auto and inherit-parent values do not satisfy this gate. An inherited requested judge is invalid. The validator checks these recorded relationships and inspected artifact existence. It cannot authenticate a provider's model identity or family assertion. Preserve that uncertainty in reports. Missing cross-family judging remains reduced parent-only selection, never a full method receipt.
